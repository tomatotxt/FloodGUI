# FloodGUI UI review — November 7, 2026

Reviewed the active FloodGUI project, including ui/main, ui/creator, ui/player,
ui/recordings, ui/service, ui/kavo, the vendored Kavo and input modules,
creator/player keyboard wiring, and the existing UI and controller harnesses.
The older Flood-GUI directory was not modified.

## Confirmed issues fixed

1. **Map-name drafts erased by background synchronization (P1).** Main UI polls
   every 0.3 seconds. Input:Get returns the currently edited text, but the model
   updates on focus loss. The poll replaced unfinished text with the old model
   value. Focused inputs now defer model-to-control synchronization.
2. **Dropdown display disagreed with selection state (P2).** Native selection
   assigned its label after invoking the adapter callback, overwriting the
   adapter's rejected or cleared selection. Native disabled checks and callback
   ordering now keep the displayed label consistent with the model.
3. **Disabled or removed key controls could capture input (P2).** Native key
   controls did not check disabled state or frame ownership. Destroying a control
   now disables/cancels its handle, and native input callbacks check ownership.
4. **Rebinding could execute another shortcut (P1).** Capture cleared its flag
   during InputBegan, allowing later listeners for that same input object to
   dispatch actions. The consumed input is retained and shared UI policy checks
   both active capture and consumed events across windows.
5. **Creator/player shortcuts could act while using UI dialogs or key capture
   (P1).** Creator input and player InputAPI now consult the shared UI guard.
   Player input also explicitly ignores focused text boxes. Release events remain
   enabled so held actions can stop.
6. **Window dragging could be stolen or remain active (P2).** A second pointer
   could replace the first; focus loss and hiding did not clear drag state.
   Drags now have one owner, end on release/focus loss/window cancellation, and
   use persistent listeners rather than adding a listener on every press.
7. **Dragging could put a window or reopen button off-screen (P2).** Movement
   now clamps the rendered object to its screen bounds, accounting for its anchor.
8. **Open dropdowns survived cancellation (P2).** Dropdowns now close on window
   cancellation, including mode/tab changes, hiding, and disabling controls.

## Verification

The full scripts/check.mjs suite passed after the final changes: 61 Lua/Luau
files compiled, all test harnesses passed, and 177 recording files were validated
(985,086 JSON frames). Added tests execute actual Kavo, adapter, and input code,
plus the actual main UI through its control harness. Cases include draft text,
rejected/cleared dropdowns, capture-event dispatch, disabled/destroyed shortcuts,
modal/typing input suppression, pointer ownership, off-screen drag, focus loss,
and hide-during-drag. Existing tests cover confirmation exact-once behavior,
mode state, holds, unload/reload, file refresh/import, preferences, and preview
cleanup. These are mocked Roblox interactions, not an in-game rendering test.

## Limits and remaining checks

This review does not establish that the UI has zero bugs. No Roblox runtime or
executor was connected. Verify visual clipping, text readability, scrolling long
recording lists, touch keyboard behavior, overlapping windows, and viewport
changes on real desktop/mobile devices. The follow-up layout pass now automatically refits and repositions windows on
ScreenGui size changes, with mocked portrait/desktop regression coverage. Native event ordering and appearance require live checks.
All categories intentionally continue to start collapsed, matching the existing
explicit regression requirement.

## Follow-up: visual consistency and responsiveness

- Sliders use a 52 px row with separate label/value and drag areas. The visible
  track stays 6 px tall; its input target is 20 px tall. Values use the requested
  step precision and suffix, avoiding long floating-point strings.
- Long control and recording names truncate inside their allocated space. Window
  titles use a full-height label; input placeholders are now honored.
- Toggles execute callbacks before ripple effects. Repeated silent updates with
  unchanged values no longer restart control rendering/animations.
- Progress controls now show a bounded fill bar alongside the percentage.
- Notification stripes use the configured success/warning/error colors.
- Windows automatically refit and clamp on ScreenGui size changes and restore
  the requested scale when space becomes available. Reopen buttons also clamp.

The full local suite passes. No actual Roblox rendering or animation performance
was observed; these are code/layout fixes with mocked interaction checks.
